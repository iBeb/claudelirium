# Extract of the Nosography of Post-Framework Disorders

**Boilerplasia (n.)** — Abnormal proliferation of boilerplate tissue: the pathological inability to let a struct stand alone. Each type acquires a constructor that does nothing but `return &T{}`, each field a getter and a setter that only read and write it, each model a near-identical DTO twin whose whole purpose is to be mapped to and from the thing it already resembles. Advanced cases present a `models/` directory shadowed by matching `request/`, `response/`, and `dto/` triplets, and a utils package that has quietly become load-bearing. Diagnosis is confirmed by excision: remove a layer and observe that nothing, anywhere, changes. **Epidemiology:** Most prevalent in the PHP world, but the tissue grows wherever ceremony was once rewarded and directness punished — Spring, .NET, and enterprise Java are all competent reservoirs. PHP is the classic host, not the only one. **Etiology:** years spent where the framework paid you by the abstraction. **Prognosis:** good, though recovery is measured in lines *removed* rather than added. Responds to aggressive `gofmt` and a reviewer who keeps asking "does this need to exist?" Invisible to `go vet`, which would be appalled if it could see it.

**Interfacitis (n.)** — Inflammation of the interface-defining reflex: the compulsion to guard every concrete type behind an interface, typically one method wide and one implementation deep, forever. Hallmarks include interfaces declared at the point of production rather than consumption, a `FooInterface` shipped preemptively for its sole `Foo`, mock files outnumbering the code they stand in for, and `type Doer interface { Do() }` written where a plain function value would have done. **Epidemiology:** Endemic to the PHP ecosystem, where an explicit implements keyword long drilled the reflex, but by no means confined to it — sporadic cases arrive with migrants from Java/Spring and C#, and any language whose compiler once demanded the ceremony. The true exposure is not PHP as such but any environment where interfaces were mandatory rather than earned. **Etiology:** prolonged obedience to an explicit `implements` contract. **Pathognomonic sign:** disbelief that Go satisfies interfaces structurally — that one may simply *not write* the interface until a second caller exists. **Prognosis:** excellent on internalizing "accept interfaces, return structs" and defining them at the call site. Relapse common in proximity to testing frameworks.

**Pehapitis (n.)** — The primary systemic infection: a whole-body conditioning of which Boilerplasia and Interfacitis are the two most common presenting lesions. Contracted through prolonged residence in the PHP ecosystem and typically asymptomatic for years, dormant, until the host is transplanted into Go — at which point the immune response, calibrated for an environment that no longer exists, turns on the new tissue. Presents as: reaching for a framework before a single handler has been written; a craving for a dependency-injection container so acute that its absence in `main.go` produces physical unease; modeling every payload as a nested map because arrays once solved everything; and a `Manager` that manages a `Handler` that handles a `Service`, delegation descending until the actual work is nowhere to be found. Advanced cases treat error not as a value to be checked but as an inconvenience to be wrapped and hurled upward until someone else's stack frame has to deal with it. **Epidemiology:** Endemic strictly to the PHP ecosystem, and here the family distinction matters: the lesions are polyetiological — Boilerplasia and Interfacitis can be acquired from any ceremony-heavy reservoir, Spring and .NET among them — but Pehapitis proper is monogamous to PHP. It is the most complete and virulent presentation known, the only host in which both lesions reliably co-occur as a single syndrome rather than in isolation. Prevalence approaches totality among long-term PHP natives at first Go exposure and falls off sharply with years since migration, though seroconversion is rarely total. **Etiology:** sole and sufficient cause is prolonged formative exposure to the PHP framework culture, where the framework did the thinking and rewarded the host for supplying ceremony in return. No co-factor is required; PHP is enough. **Prognosis:** good, and better the earlier it is caught — read the standard library, delete two-thirds of the abstractions, and sit quietly with the discomfort of a package that simply works with nothing holding it up. Full remission is achievable; many recovered hosts nonetheless retain a lifelong flinch at an empty `main.go`. Named for the phonetic recitation of the pathogen — pe-ha-pe, the only pronounceable form — the letters themselves resisting Latin as stubbornly as the habits resist Go.
