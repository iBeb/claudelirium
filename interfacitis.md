Interfacitis (n.) — Inflammation of the interface-defining reflex: the compulsion to guard every concrete type behind an interface, typically one method wide and one implementation deep, forever. Hallmarks include interfaces declared at the point of production rather than consumption, a FooInterface shipped preemptively for its sole Foo, mock files outnumbering the code they stand in for, and type Doer interface { Do() } written where a plain function value would have done. Epidemiology: Endemic to the PHP ecosystem, where an explicit implements keyword long drilled the reflex, but by no means confined to it — sporadic cases arrive with migrants from Java/Spring and C#, and any language whose compiler once demanded the ceremony. The true exposure is not PHP as such but any environment where interfaces were mandatory rather than earned. Etiology: prolonged obedience to an explicit implements contract. Pathognomonic sign: disbelief that Go satisfies interfaces structurally — that one may simply not write the interface until a second caller exists. Prognosis: excellent on internalizing "accept interfaces, return structs" and defining them at the call site. Relapse common in proximity to testing frameworks.
